# Atlas Studio MVP

## Цель

Atlas Studio объединяет разрозненные сценарии Atlas в один рабочий конвейер для выбранного AI-персонажа:

`персонаж → Character Brain → референсы → генерация → библиотека → контент → approval → публикация`

Atlas остаётся внутренней контент-фабрикой владельца, а не публичным кредитным SaaS.

## Пользовательский сценарий

1. Пользователь выбирает одного персонажа.
2. Atlas показывает готовность персонажа и недостающие элементы.
3. Пользователь запускает одно из четырёх действий:
   - создать лицо;
   - создать сцену;
   - загрузить фото и выполнить face-swap;
   - создать неделю контента.
4. Результаты генерации сохраняются в библиотеку выбранного персонажа.
5. Изображение прикрепляется к публикации.
6. Публикация проходит ручное согласование и обязательный AI-disclosure.

## Первый UI-срез

### Переключатель персонажей

Для каждой модели показываются:

- аватар;
- имя и ниша;
- статус;
- индикатор готовности;
- количество референсов;
- количество материалов в работе.

Данные разных персонажей не смешиваются.

### Карточка готовности

Готовность рассчитывается без новой схемы базы данных:

- Character Brain: заполнены `bio`, `tone`, `biography`, `immutable_facts`;
- Identity: существует `visual_passport.avatar`;
- References: существуют записи `model_references`;
- Distribution: существуют `social_accounts`;
- Production: существуют `content_items` выбранного персонажа.

### Быстрые действия

- `Создать лицо` открывает существующий Avatar Studio в режиме `avatar`.
- `Создать сцену` открывает Avatar Studio в режиме `scene`.
- `Загрузить фото` открывает Avatar Studio в режиме `faceswap`.
- `План на неделю` открывает существующий Week Planner с выбранным персонажем.

### Последние генерации

Показываются последние задания выбранного персонажа:

- тип;
- статус;
- дата;
- превью результата;
- ошибка при неудаче;
- переход к сохранению в reference library или прикреплению к публикации.

### Контент в работе

Показываются последние `content_items` выбранного персонажа:

- название;
- площадка и формат;
- статус;
- дата публикации;
- наличие визуала;
- наличие disclosure.

## Ограничения первого релиза

- Новая схема Supabase не создаётся.
- RLS и ownership backfill не меняются.
- GPU не запускается автоматически.
- Массовая генерация для всех персонажей отсутствует.
- Все платные действия остаются за явной кнопкой и Cost Governor.
- Approval gate и обязательный AI-disclosure не обходятся.
- Видео не входит в первый релиз. Оно добавляется после подтверждения стабильности изображений и identity consistency.

## Definition of Done

- Владелец выбирает персонажа и видит его готовность на одном экране.
- С одного экрана доступны четыре ключевых производственных действия.
- Последние генерации и контент выбранного персонажа видны без перехода между разделами.
- Никакие данные других персонажей не попадают в выбранный контекст.
- `npm run build`, lint non-regression и project-state check проходят.
- Тесты не вызывают OpenAI или Modal.
